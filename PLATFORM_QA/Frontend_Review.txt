Code Review — PR #3 fix(qa): platform QA — 14 bugs fixed (max effort)

Scope: 17 src/ files (the PLATFORM_QA/ docs/screenshots/Lighthouse output is out of scope). Base dev/parthib/UI ← qa/platform-health. Method: 7 finder angles + 1 gap sweep, each candidate verified against the actual code (I read the API client, useApi, AuthContext, both layouts, and every touched render site).

The PR is mostly sound — the skipAuth removals are safe for anonymous users (AuthContext keeps token+user atomic and refreshes-or-clears on boot), pathname is correctly in scope, and the new optional type fields default safely. The findings below are the real residue.

Findings (ranked)

1 🔴 Incomplete BUG-014 fix — onboarding doc upload still 400s. onboarding/page.tsx:75 still does fd.append('file', file) against /advocate/documents, the exact endpoint+field the PR says the backend rejects (FileInterceptor wants 'document'). Only documents/page.tsx was patched; this is the primary upload site (onboarding step 4). Advocates can't submit verification docs → can't get verified. Fix: change 'file' → 'document' here too.

2 🟠 Citizen sidebar "Find Advocates" link ejects the user from the console. Moving /advocates to (public)/(with-nav) (BUG-003) means the citizen NAV item at (citizen)/layout.tsx:28 now lands on a page rendered under the public Navbar/Footer layout, without the SidebarProvider. A logged-in citizen loses their sidebar and has no in-console way back; pathname.startsWith('/advocates') active-state never applies. Fix: add an authenticated alias route (e.g. keep a thin (citizen)/advocates that renders the shared page) or render the directory inside the citizen shell for logged-in users.

3 🟡 i18n regression — hardcoded English in the new close/feedback UI. matters/page.tsx adds 5 user-facing strings outside t()/tr(): "Feedback submitted" (168), "Consultation closed" (201), "Failed to close" (204), "Confirm close?" / "Close consultation" (219). In a bilingual app whose PR title claims i18n cleanup, Bengali users see English. Fix: add matters.* keys (EN+BN) and use tr(...).

4 🟡 AI-brief shows duplicate/un-normalised classification badges. ai-brief.tsx:90-91: the matterType badge renders displayPracticeArea(c.matterType) (normalised) but the dedup guard compares raw (c.primaryDomain !== c.matterType) and renders c.primaryDomain raw. With matterType='criminal_matter', primaryDomain='Criminal' you get two badges both reading "Criminal"; with a raw primaryDomain slug you get a snake_case badge beside a normalised one. Fix: normalise both sides and compare the normalised values.

5 🟡 displayPracticeArea crashes on a null/empty array element. advocate-card.tsx:28 calls raw.toLowerCase() with no guard. The &&-guarded matterType callers are safe, but element-map callers — advocate-card.tsx:73 practiceAreas.slice(0,4).map(...) and advocates/[id]/page.tsx:87 p.practice_areas?.map((a)=>displayPracticeArea(a)) — guard the array, not its elements. A [null]/[''] payload (the same malformed-data class the new ?? [] defends against) throws and blanks the page. Note the ?? [] defense was added only in AdvocateCard — the detail page and other consumers remain exposed. Fix: guard inside displayPracticeArea (if (!raw) return '') — one place covers all callers.

6 🟡 [pathname] refetch is both too eager and too weak. (citizen)/layout.tsx:46 and advocate/layout.tsx:46 now refetch /user/me / /advocate/me on every in-app navigation — a full profile GET per sidebar click — yet still miss the in-place case (editing avatar/profile without navigating leaves the sidebar stale). Fix: invalidate on the profile/avatar/onboarding mutation (or push the updated profile into AuthContext) instead of keying off pathname; the two layouts otherwise duplicate this hack.

7 🟡 Three independent sources of truth for practice areas. PA_DISPLAY (slug→label, advocate-card.tsx:17), the directory filter list (advocates/page.tsx:19, Title-Case), and lib/constants.ts PRACTICE_AREAS must agree but aren't linked. The filter sends Title-Case ('Civil') while records hold slugs (corporate_law); display normalisation can't fix a query/stored mismatch, so a card shown as "Civil" may not appear under the "Civil" filter, and adding an area means editing 3 files in lockstep. Fix: one canonical slug→bucket map at the data boundary; derive the filter list from it.

8 🟡 skipAuth handled two opposite ways for the same concept. Matter pages dropped skipAuth (send token if present), while advocates/[id]/page.tsx:34-36 (×3) and advocates/page.tsx:37 keep skipAuth:true for structurally identical optional-auth public endpoints. If the backend later personalises advocate results for logged-in users, those pages silently send the anonymous view. Fix: a single auth:'optional' request flag applied uniformly.

9 🟢 Bespoke confirm pattern, fragile + inconsistent. CloseConsultationButton (matters/page.tsx:193) uses a two-click confirm whose onBlur={() => setConfirming(false)} cancels on any focus shift (tooltip, scroll-tap, SR navigation), while cancelBooking in the same file (line 57) uses window.confirm and decline uses a Dialog. Three idioms, no shared AlertDialog. Fix: one shared confirm primitive built on the existing Dialog.

10 🟢 Dead code / misplaced util in displayPracticeArea. advocate-card.tsx:28: the middle lookup ?? PA_DISPLAY[raw] is unreachable (every key is lowercase and the first lookup already lowercases raw). Also this pure formatter lives in a UI component yet is imported by 4 other modules — it belongs in lib/. Fix: drop the dead branch; move to lib/format (or lib/practice-areas).

11 🟢 Narrow stale-token regression on public matter pages (plausible, low). matter/[id]/page.tsx:28,30: removing skipAuth means a logged-in-but-stale-token visitor hits the 401→refresh-retry path on a public read; if refresh fails the matter/advocates panels error where skipAuth:true always rendered the public view. Largely mitigated (AuthContext clears tokens on failed refresh at boot) — only a narrow async-boot window survives. Fix (defensive): on a 401 whose refresh fails, retry once without the bearer token, or scope it as auth:'optional' per #8.
